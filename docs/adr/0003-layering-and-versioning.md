# ADR 0003: Слои модели и версионирование артефактов

- Статус: принято (accepted), v0.1.0
- Дата: 2026-09-07
- Область: JSON Schema, `docs/federated-exchange-document.md`, README

## Контекст

В v0.0.8 корневой тип `FederatedExchangeDocument` (полный снимок федерации)
и транспортный `ExchangeEnvelope` были смешаны: правила секции 1 описывали
документ, которого нет ни в одном примере обмена; `$id` схем указывали на
ветку `main` (мутирующий URL); имена полей-контейнеров были непоследовательны
(`federationnode`, `digitalobject` против snake_case остальной модели).

## Решение

1. **Слои явно разведены.** Единица обмена между узлами — `ExchangeEnvelope`
   (все примеры валидируются против него). `FederatedExchangeDocument` —
   снимок состояния федерации: артефакт экспорта/резервирования, в обмене
   напрямую не участвует. Правила секции 1 (rules.dsl) применяются к снимку,
   секции 6 — к конверту.
2. **Имена полей приведены к единому стилю:** `federation_nodes`,
   `digital_objects`, `persons`, `relations` (в `FederationNode` и корне);
   разделы карточки (`metadata`, `classification`, `license`) сохранены.
3. **`$id` версионированы по тегу** (`…/v0.1.0/schema/…`), а не по `main`:
   консьюмеры протокола ссылаются на неизменяемые версии. Каждый релиз
   протокола = тег + обновление `$id` + запись в CHANGELOG.
4. **Семантическое версионирование:** MAJOR — несовместимые изменения
   контракта; MINOR — новые возможности (v0.1.0: условные требования,
   relation_type, подтверждения, тесты/CI); PATCH — исправления без изменения
   контракта. До 1.0.0 MINOR может ломать обратную совместимость — фиксируется
   в CHANGELOG.
5. **Часть правил перенесена в JSON Schema** (UUID v4 lowercase, RFC 3339 UTC,
   `entity_type` ⇒ `work_guid`/`manifestation_guid`+`owner_node_guid`,
   `status` ⇒ `claims`); остальные правила проверяются тестовым набором
   (см. `/tests`), а не только прозой.

## Последствия

- Схемы стали проверяемой спецификацией: невалидные карточки
  (Manifestation без work_guid и т.п.) отклоняются валидатором, а не только
  правилами.
- Прямые ссылки на `main`-версии схем (например, в чужих публикациях) более
  не рекомендуются — только по тегу.
- Правила DSL остаются нормативным текстом + маркером «выражено в схеме /
  проверяется тестами» до появления полноценного интерпретатора.
