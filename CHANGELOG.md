# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/);
версионирование — [SemVer](https://semver.org/lang/ru/) (до 1.0.0 MINOR может

## [v0.1.0] — 2026-09-07

Схемы, правила и доки приведены к единой проверяемой спецификации.

### Добавлено

- **Тесты и CI**: проверяемый набор правил (`tests/`) — мета-валидация схем,
  позитивные примеры обмена, негативные фикстуры на правила, выраженные в
  JSON Schema; GitHub Actions workflow (`.github/workflows/ci.yml`).
- **Строгие типы в JSON Schema** (`$defs.Uuid4`, `$defs.TimestampRfc3339Utc`):
  UUID v4 lowercase и RFC 3339 UTC с суффиксом `Z` (без произвольных offset)
  проверяются валидатором, а не только форматом.
- **Условные требования `entity_type`**: Manifestation ⇒ `work_guid`;
  Item ⇒ `manifestation_guid` + `owner_node_guid` (`allOf/if/then`).
- **`relation_type`**: базовый словарь `same_as` / `duplicate_of` + расширение
  через `authority`; поле переименовано из `relation` (⚠️).
- **Доказуемость подтверждений**: `Relation.confirmed_by_node_guid` и
  `modified_at`; смена статуса — новая версия той же связи по `relation_guid`.
- **`Metadata`: `status` ⇒ `claims` обязательны** (статус без заявлений невалиден).
- **`Person.owner_node_guid`** — явная пара владельца `(owner_node_guid, person_guid)`.
- **ADR**: `docs/adr/0001` (бутстрап без оператора — git-реестр),
  `0002` (доказуемость подтверждений), `0003` (слои и версионирование).
- **CHANGELOG.md**, sequence-диаграмма сценария А/Б в доке.

### Изменено

- **Слои разведены** (⚠️): единица обмена — `ExchangeEnvelope`;
  `FederatedExchangeDocument` — полный снимок состояния (экспорт/резерв),
  в обмене напрямую не участвует. Правила секции 1 rules.dsl применяются к снимку.
- **`$id` схем версионированы по тегу** `…/v0.1.0/schema/…` вместо `main` (⚠️
  для прямых ссылок на `main`).
- **Имена полей-контейнеров унифицированы** (⚠️): `federation_nodes`,
  `digital_objects`, `persons`, `relations` (было `federationnode`,
  `digitalobject`, `person`, `relation`).
- **`NodeType` сужен** до `FederationNode` / `DigitalObject` / `Person` (⚠️):
  Work/Manifestation/Item — значения `entity_type` карточки, а не адресуемые
  типы связи.
- **`digital_object_media_url` — опционально**: абстрактный Work может не иметь
  цифровой репрезентации (правило `object.media` — рекомендация с `warn`).
- **UML-диаграмма синхронизирована** со схемой (классы `Relation`, `Person`,
  комментарии о концептуальных уровнях).
- Правила DSL: секция 1 переименована («снимок состояния»), добавлены
  `document.timestamp`, `metadata.claims_status`, `relation.types`,
  `relation.versioning`, `ai.license_gate`.
- Примеры обмена: версия `0.1.0`, `owner_node_guid` у персон, `relation_type`
  + `confirmed_by_node_guid`/`modified_at`, исправлены несостыковки дат
  (встречное заявление А теперь внутри окна конверта), персона А добавлена
  в контекст таргетированного конверта.

## [v0.0.8] — 2026-09-02

- Claims с провенансом вместо единого канонического значения: `Claim[]`,
  статусы атрибута `unresolved` / `canonical` / `rejected`.
- Явная политика разрешения конфликтов: N≥2 независимых подтверждений
  (конфигурируемый дефолт), окно оспаривания, fallback первого регистратора.
- Идентичность vs истинность: первый регистратор — право управления локальной
  записью, не критерий истинности атрибутов.
- Matching и acceptance — раздельные события; `rights_holder_confirmation`.
- Примеры: карточки Work/Manifestation с `entity_type`, claims со статусом
  `unresolved` в таргетированном конверте.

## [v0.0.7] — 2026-08-31

- Модель сущностей Work / Manifestation / Item (`entity_type`, `work_guid`,
  `manifestation_guid`, `owner_node_guid`); правило первого регистратора;
  Items разных узлов не дубликаты.

## [v0.0.6] — 2026-08-31

- Узел `License` (код + authority; НКО — допустимый авторитетный источник);
  `is_enabled_for_ai_using` (консервативный дефолт: отсутствие = запрет);
  правила использования данных в ИИ; enforcement через правовое поле —
  протокол даёт доказуемость.

## [v0.0.5] — 2026-08-31

- Границы скоупа: транспорт/подписка/TLS — вне протокола; мастер-запись не
  выделяется; классификатор — следующий шаг.

## [v0.0.4] — 2026-08-31

- Асинхронный протокол: единый конверт `publish`, два режима через
  `receiver_node_guid` (broadcast-снимок / таргетированный возврат вклада);
  дедупликация — локальная операция узла.
- Экспертная атрибуция (`Person`), идентичность персоны узловая; пример на
  реальном объекте (каталог РГПУ).
